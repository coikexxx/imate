# M3 团队协作 Implementation Plan

> **For agentic workers:** 计划文首的 superpowers 技能只是一种执行方式。本仓库按 `AGENTS.md` 执行：确认前不要改实现；确认后从下文分支按 Task 顺序做，先写测试并确认失败，再实现，每 Task 一次本地提交。
>
> 状态：待用户确认。2026-11-11 起草。M2 的三项未验收不在本计划内补做。

**Goal:** 一条用户指令由组长研判，可以直接答复、组织最多 3 轮并行讨论，或派工后串行执行并验收。运行中的插话、点名和停止按边界入队。重启后指令可解释，不自动重跑。

**Architecture:** 新增 `orchestrator`，复用现有 `runner`、适配器和 `ChatService` 的提示词与游标。SQLite 只在迁移数组末尾追加，不改 v1 脚本。状态机用 `FakeAdapter` 测试，不启动真实 CLI。前端在“等待用户”时提供重试、补充和放弃。

**Tech Stack:** 与 M2 相同：Tauri 2、Rust edition 2024、rusqlite、React 19、TypeScript、Vitest。不新增依赖。

**Spec:** `docs/MVP开发手册.md` 第 4 节、第 5 节规章版本通知、第 6 节 M3 追加状态、第 7 节指令与任务接口、第 9 节异常处理、第 11 节 M3 验收。

## Global Constraints

- 界面文案、报错、注释、提交信息使用简体中文。技术术语保留英文。
- 前后端 JSON 一律 camelCase。
- 不修改已发布的 v1 迁移脚本。M3 表和列只追加。
- 不改 `ChatService`、`resolve_recipient`、`build_opening`、`build_turn_prompt` 的既有函数名。新行为加新函数。
- 成员匹配使用 `trim().to_lowercase()`，与 `chat::resolve_recipient` 一致。发现旧数据冲突时拒绝迁移，不自动改名。
- 空闲时以 `@成员` 开头的消息仍是直接执行指令，不经过组长。其他消息进入团队指令。
- 协议只解析 `TurnCompleted.final_text` 末尾唯一闭合的 `imates` 围栏。正文里的 JSON、其他代码块和弯引号修复都不算指令。
- 讨论轮最多 3，单任务返工最多 2，单条指令实际 CLI 尝试最多 30。并行启动前一次预留名额。
- 执行失败不自动重试。只对讨论模式、无工具调用、明确可重放的短暂失败自动补救一次。协议纠错也占用这一个额度。
- 落库事务不跨越进程启动。重启把 running run 标为 interrupted，执行中任务标为 failed，未启动任务和队列取消，未结束指令转为 waiting_user，不自动重跑。
- 不实现 M4 文件树和像素办公室、M5 其余适配器、M6 设置页，也不做自动回滚、精确费用上限或 MCP。
- 不补做 M2 留下的三项：macOS Claude 2.1.322 工具层拒写、Finder/Dock PATH、应用窗口异常退出和清理确认点击。
- 只本地提交，不推送。真实 CLI 不在仓库目录里以执行模式运行。
