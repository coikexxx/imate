# M2 单 Agent 对话实施计划

> 状态：Task 1–10 实现完成，Task 11 文档及自动化收尾完成；M2 实际验收未闭环。G1/G2 已完成；按用户确认，Claude Discuss 权限证据记为“模式已核对、工具层拒写未验证”，继续实现且不宣称硬隔离。Claude 工具层拒写、Finder/Dock PATH、异常恢复及 Windows runner 验收仍待完成。

**目标：** 在项目页提供可持久化的单 Agent 群聊；接入 Claude Code 与 Codex CLI，支持 `@成员`、停止、上下文注入和助理草稿。权限证据如实标为事件回显、精确版本行为实测或未验证。满足 MVP 手册第 11 节 M2 验收。

**范围：** M2。只接入 Claude、Codex；不实现组长多轮讨论/派工编排（M3）、文件树/文件监听/办公室（M4）、Grok/dsh/pi（M5）、设置页与安装包（M6），也不增加用户自定义 CLI 注册配置。

**架构：** Rust/Tauri 管理 SQLite、CLI 子进程、会话和运行状态。前端通过 commands 发送请求，通过 Tauri events 接收运行状态与输出。每条消息启动一个 CLI 进程；会话由 CLI 的 session/thread ID 续接。进程流、停止、超时和进程树清理归 runner 负责。M2 是单 Agent 对话：普通消息直接交给组长处理，`@成员` 直接交给被点名成员；均为单个 Agent 执行回合，不要求或解析 M3 的组长指令 JSON、不创建协作任务。M3 再接入团队讨论和派工。

**技术栈：** 现有 Tauri 2、Rust 2024、rusqlite、serde_json、React 19、TypeScript、Vitest；新增 `tokio`（process、io-util、sync、time、macros、rt-multi-thread）、`libc`（Unix 进程组信号）、`zustand`（运行事件状态）。不引入其他依赖。

**设计依据：** `docs/MVP开发手册.md` 第 2–5、6–11 节；`docs/CLI实测记录.md` 的 Claude、Codex 部分；真实样本 `src-tauri/tests/fixtures/{claude,codex}/`。适配器解析只以脱敏样本为准，Windows 样本不能代替 macOS 验收。

**实施前置门：** G1 同一 Codex 会话 `Discuss → Execute → Discuss` 沙箱与续接验证、G2 Codex 用量语义调查及 G3 CLI 基线须先完成。G1/G2 已完成；G3 Claude Discuss 仅验证模式回显、未获得工具层拒写证据，按用户确认继续并如实标记未验证。G3 macOS 桌面环境 PATH、runner 取消/进程树与应用验收留 Task 11；未通过前不标 M2 完成。不以 fixture 或 `--help` 冒充真实验证。

**阶段边界：** M2 普通消息由组长作为单个 Agent 直接处理，`@成员` 由目标成员直接处理，不模拟 M3 讨论/裁定。M2 同项目只允许一个活动回合，运行中拒绝新消息；持久化插话队列和 M3 调度语义不在本次实现。保留 M2 助理起草，不拆 M2b；助手拆分只是进度选择，不是架构整改条件。禁止新增精确 token/费用硬上限、危险操作审批、自动回滚或周期性会话轮换。

## 全局约束

- 只在 `feat/m2-single-agent` 分支开发；不推送。
- UI 文案、错误信息、注释和提交信息用简体中文；前后端 DTO 均使用 camelCase。
- 新增代码先写测试并确认失败，再写实现并确认通过。每个 Task 独立提交；提交时同步勾选计划步骤。
- Agent 的工作目录由 runner 的 `current_dir` 设置。执行模式可写出工作目录，用户和项目 CLI 配置可能被继承；UI 明示实际边界，适配器不承诺沙箱隔离或全局配置隔离。
- 提示词经 stdin；不把提示词放命令行。M2 Codex 命令不带 `-C`，以 `current_dir` 为准；实测记录保存 M0 原始命令作为历史证据。
- 成功需同时满足完成事件、exit code 0、无致命错误、未取消、未超时。失败/取消/超时终态一旦写入不能被迟到完成事件覆盖。保留部分回答并显示明确错误；未知 JSON 行不终止进程。stderr 只保留有限尾部，不存令牌。
- 普通消息路由组长；显式点名但成员不存在时拒绝发送并显示错误，不静默改派。收到带 `imates` JSON 的正文时按普通 Agent 文本展示，M3 才解析指令协议。
- 重启后残留 running run 标 interrupted、项目 waiting_user。正常退出先取消并等待项目/助理清理；异常退出不保证进程组自动消失。持久化运行所有权及 cwd 清理待确认标记，未确认清理前拒绝同目录新运行，不仅凭 PID 盲杀；不得自动重放可能已写文件的回合。
- 助理只读运行且仅返回可编辑草稿；必须由用户确认后才调用保存接口。UI 保存 draftId，后端保存与该草稿绑定的 CLI sessionId；关闭草稿时一并释放。
- 当前数据库版本 1 已有 `messages`、`runs`、`agents.session_id`、`agents.last_seen_message_id`、`settings`；本计划复用现有 schema。SQL 中存在的 session/cursor 尚未由 Agent DTO 暴露，需要补上存取函数；不改写版本 1 迁移。
- 实时运行事件使用手册第 7 节固定契约和 camelCase 载荷；UI 按 `projectId/runId/seq` 去重。刷新通过只读快照恢复活动回合；事件增量是整段文本/工具事件，不宣称逐 token 打字。
- CLI 原生用户配置与项目 `AGENTS.md`/`CLAUDE.md` 不做隔离。M2 仅记录其继承边界，不猜测 hooks/MCP/插件的启用情况，不调用未经验证的禁用开关。
- 不在仓库目录执行 CLI。真实 CLI 验收只在仓库外的新建临时项目目录进行；不保存该目录内容、用户主目录路径或凭据到仓库。
- Claude `plan` 会在其自身计划目录写文件，属于 M0 已知行为；计划提示词要求只读，但不声称该模式是强隔离。Codex resume 样本没有权限回显字段，不能显示未验证的权限保证。

## 附录 A：事件与用量契约

- `message:delta`：`{ projectId: string, runId: string, seq: number, agentId: string, text: string }`。seq 从 1 开始，在同一个 run 内递增。
- `message:new`：`{ projectId: string, runId: string | null, message: Message }`。消息以 SQLite 自增 id upsert。
- `agent:status`：`{ projectId: string, agentId: string, runId: string | null, status: "idle" | "thinking" | "talking" | "working" | "error" }`。
- `run:finished`：`{ projectId: string, runId: string, agentId: string, seq: number, status: "ok" | "failed" | "timeout" | "cancelled", error: string | null }`。seq 为本 run 的最终序号，终态后拒绝迟到增量与状态。
- `assistant:delta`：`{ draftId: string, runId: string, seq: number, text: string }`。草稿生成事件不得进入项目群聊。
- `get_project_runtime` 返回 `{ active: RuntimeSnapshot | null, cleanupRequired: CleanupNotice[] }`；RuntimeSnapshot 为 `{ projectId, runId, agentId, status, seq, partialText }`，CleanupNotice 为 `{ runId, projectId: string | null, folderPath }`。快照过滤同目录的助理残留；前端先订阅再加载，按 runId/seq 去重。确认为人工清理完成后调用 confirm_runtime_cleanup，不宣称应用已自动杀死残留。
- `Usage`：输入/输出/cache-read/cache-write token 都是 `Option<u64>`；费用为 `Option<f64>`，另有 `rawUsage: Value | null` 仅保存原始用量对象供累计对照。存储 JSON 用 camelCase。未上报或未确认属于本回合的值保留为 None，不假造 0；不要把 Codex cached input 再加到 input。
- 每条已知 TextDelta 同步更新 Agent 占位消息正文和 RuntimeSnapshot；Final 正文覆盖占位消息，避免重复追加 adapter 的 final result。

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::store::{open_in_memory, projects};

    #[test]
    fn pagination_is_scoped_and_returns_latest_messages_in_order() {
        let conn = open_in_memory().unwrap();
        let a = projects::create(&conn, "项目甲", "", "/tmp/甲").unwrap();
        let b = projects::create(&conn, "项目乙", "", "/tmp/乙").unwrap();
        let first = insert(&conn, &a.id, "user", None, "chat", "第一条").unwrap();
        insert(&conn, &b.id, "user", None, "chat", "不能混入").unwrap();
        let second = insert(&conn, &a.id, "system", None, "system", "第二条").unwrap();
        let third = insert(&conn, &a.id, "user", None, "chat", "第三条").unwrap();
        let page = list(&conn, &a.id, None, 2).unwrap();
        assert_eq!(page.iter().map(|m| m.id).collect::<Vec<_>>(), [second.id, third.id]);
        let previous = list(&conn, &a.id, Some(second.id), 2).unwrap();
        assert_eq!(previous.iter().map(|m| m.id).collect::<Vec<_>>(), [first.id]);
        update_content(&conn, third.id, "已经完成").unwrap();
        assert_eq!(list(&conn, &a.id, None, 1).unwrap()[0].content, "已经完成");
    }

    #[test]
```

```rust
pub fn resolve_recipient<'a>(
    text: &'a str,
    agents: &'a [crate::store::agents::Agent],
) -> crate::error::AppResult<(&'a crate::store::agents::Agent, &'a str)> {
    use crate::error::AppError;
    let text = text.trim();
    if text.is_empty() { return Err(AppError::Invalid("消息不能为空".into())); }
    if let Some(mention) = text.strip_prefix('@') {
        let mut matches = Vec::new();
        for end in mention.char_indices().filter(|(_, c)| c.is_whitespace())
            .map(|(i, _)| i).chain(std::iter::once(mention.len())) {
            let key = mention[..end].trim().to_lowercase();
            let found: Vec<_> = agents.iter()
                .filter(|agent| agent.name.trim().to_lowercase() == key).collect();
            if found.len() > 1 {
                return Err(AppError::Invalid("成员名归一后有冲突，请先修改名称".into()));
            }
            if let Some(agent) = found.first() {
                matches.push((*agent, mention[end..].trim(), end));
            }
        }
        matches.sort_by_key(|(_, _, end)| std::cmp::Reverse(*end));
        let Some((agent, prompt, _)) = matches.into_iter().next() else {
            return Err(AppError::Invalid("未找到被点名的成员，请从成员列表选择".into()));
        };
        if prompt.is_empty() { return Err(AppError::Invalid("点名后请填写消息内容".into())); }
        return Ok((agent, prompt));
    }
    let leader = agents.iter().find(|agent| agent.is_leader)
        .ok_or_else(|| AppError::Invalid("项目没有组长，请先配置成员".into()))?;
    Ok((leader, text))
}
```

### B7：运行注册与 command 接线（Task 7）

活动注册采用下面完整 helper；放 commands.rs，watch 的 bool 由 false 变 true 表示取消。`remove` 必须比对 runId，旧任务晚到不能清掉新回合。测试阶段先建立单元测试调用这些方法，编译确认缺失，再加实现。

```rust
#[derive(Default)]
struct ActiveRuns {
    runs: std::collections::HashMap<String, (String, tokio::sync::watch::Sender<bool>)>,
    directories: std::collections::HashMap<std::path::PathBuf, String>,
}

impl ActiveRuns {
    fn reserve(&mut self, project_id: &str, run_id: &str)
        -> crate::error::AppResult<tokio::sync::watch::Receiver<bool>> {
        if self.runs.contains_key(project_id) {
            return Err(crate::error::AppError::Invalid("项目正在运行，请先停止或等待完成".into()));
        }
        let (sender, receiver) = tokio::sync::watch::channel(false);
        self.runs.insert(project_id.into(), (run_id.into(), sender));
        Ok(receiver)
    }

    fn cancel(&self, project_id: &str) {
        if let Some((_, sender)) = self.runs.get(project_id) { let _ = sender.send(true); }
    }

    fn reserve_directory(&mut self, canonical_dir: &std::path::Path, run_id: &str)
        -> crate::error::AppResult<()> {
        if self.directories.contains_key(canonical_dir) {
            return Err(crate::error::AppError::Invalid("该工作目录正在执行其他回合".into()));
        }
        self.directories.insert(canonical_dir.to_path_buf(), run_id.into());
        Ok(())
    }

    fn remove(&mut self, project_id: &str, run_id: &str) {

        }
    }
```

### B8：前端去重测试（Task 8）

新增 `src/stores/project.test.ts` 并列入本 Task Files。以 vanilla Zustand store 作为测试入口，避免依赖 DOM。`applyDelta` 为独立纯函数，类型及完整实现如下；快照先覆盖同一 run 的 text/seq，再重放缓冲的更大 seq 事件。

```ts
export interface StreamText { projectId: string; runId: string; seq: number; text: string }
export interface TextDelta { projectId: string; runId: string; seq: number; text: string }

export function applyDelta(current: StreamText, delta: TextDelta): StreamText {
  if (delta.projectId !== current.projectId || delta.runId !== current.runId) return current;
  if (delta.seq <= current.seq) return current;
  return { ...current, seq: delta.seq, text: current.text + delta.text };
}
```

### B10：草稿确认与关闭状态（Task 10）

纯函数放 `src/lib/drafts.ts`，配套完整测试如下。`canApplyDraft` 只决定 UI 能否接受草稿，实际数据库/文件写入只能从对应显式确认事件发起；不能放在 useEffect 或生成完成回调里自动保存。

```ts
import type { RuleDoc } from "../types";
import { validateRules } from "./wizard";

export function canApplyRules(rules: RuleDoc[], busy: boolean, closed: boolean): boolean {
  return !busy && !closed && validateRules(rules) === null;
}

export function acceptDraftResponse<T>(
  activeDraftId: string | null, responseDraftId: string, value: T,
): T | null {
  return activeDraftId !== null && activeDraftId === responseDraftId ? value : null;
}
```

### G1：Codex 首次、同模式与跨模式续接

旧计划记录过 0.167.0 帮助中 exec/resume 接受 `-c/--json/--skip-git-repo-check`、resume 不接受 `-s`；实施时先记录当前系统与 CLI 精确版本。帮助只证明参数被接受，不能证明权限生效。调用者先切到临时项目目录，runner 则通过 current_dir 设置；下面示例不使用 `-C`。
