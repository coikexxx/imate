# 运行记录：记录每次运行实际使用的模型 实施计划

> **给执行 Agent：** 使用 `superpowers:subagent-driven-development` 逐 Task 执行。步骤用 `- [ ]` 勾选，随该 Task 的提交一起提交。动手前先读 `AGENTS.md`。
>
> **本计划的写法说明：** 本功能要接入的位点分散在多个已有函数里（直接点名路径、编排路径、助理草稿），计划只给出行为、接口名和测试要求，不贴完整代码；执行者先用 grep 找到现有的 `SessionStarted` 写入点、`TurnRequest { .. model .. }` 构造点和 `messages::insert(.., "agent"|"assistant", ..)` 调用点，再按下面的要求接线。找不到对应位点或位点数量与计划描述不符时，停下来报告，不要猜。

**目标：** 每次 CLI 运行把「请求的模型」和「CLI 报告的模型」记进运行记录；群聊里每条成员消息旁显示这次运行用的模型。历史记录不回填，只对新运行生效。

**架构：** 新增事件 `AgentEvent::ModelReported`（Claude、Grok 的适配器在 `system init` 里读出 `model`）；沿用 `SessionStarted` 写 `runs.session_id` 的方式，把它写进 `runs.reported_model`；启动回合时把有效模型写进 `runs.requested_model`；`messages.run_id` 把每条成员消息链到产生它的运行，`list_messages` 联表带出两个模型值；前端在消息发送者名字旁显示。

**技术栈：** Tauri 2、Rust（rusqlite）、React 19、TypeScript、vitest。

## 全局约束

- 语言：界面文案、报错信息、代码注释、提交信息、文档一律简体中文。JSON 字段 camelCase。
- 不新增依赖；不要推送，只在本地提交；分支 `feat/run-model-record`（已建好，不要切换）。
- **不回填历史**：迁移只加列，不改已有行；旧消息、旧运行的新字段保持为空，界面对它们不显示模型。
- 不读 Codex 的会话文件来反推模型；Codex、Dsh 的事件里没有模型字段，只记「请求的模型」。
- 「请求的模型」= 实际传给适配器的 `TurnRequest.model`，即成员自己填的模型，或回落到 CLI 默认模型之后的值；为空表示由 CLI 自己决定。
- 报告的模型来自 CLI 事件流里的 `model` 字段（长度 ≤ 200、不含控制字符才接受），不是请求值的复述。
- 后端测试串行：`cd src-tauri && cargo test -- --test-threads=1`；若报 `frontendDist` 路径不存在，先在仓库根目录执行一次 `npm run build`。若 `cargo build` 因本机运行中的 `imates.exe` 链接失败，不要结束该进程，改用 `cargo check` 并在报告里说明。
- 不得读取用户真实的 `~/.codex`、`~/.claude` 配置；测试只用仓库里的录制样本（`src-tauri/tests/fixtures/*`）与内存数据库。
- 计划里没有的代码按现有风格写；不得削弱已有测试。

### Task 2: 消息链接到运行，并在读取消息时带出模型

**Files:** `src-tauri/src/store/messages.rs`，以及创建成员消息的位点：`commands.rs`（直接点名的占位消息，两处 `messages::insert(.., "assistant", ..)`）、`orchestrator/mod.rs`（`apply_execute`、`apply_member_discuss`、`save_speech` 的调用方、`apply_mention` 等所有 `messages::insert(.., "agent", ..)`）。

**Interfaces:**
- Consumes：Task 1 的列。
- Produces：
  - `messages::set_run(conn: &Connection, message_id: i64, run_id: &str) -> AppResult<()>`
  - `Message` 增加 `pub model_info: Option<ModelInfo>`，其中 `#[serde(rename_all = "camelCase")] pub struct ModelInfo { pub requested_model: Option<String>, pub reported_model: Option<String> }`；消息没有链接的运行时为 `None`（旧消息永远是 `None`）。
  - `messages::get` 与 `messages::list` 联表 `runs`（`LEFT JOIN runs ON runs.id = messages.run_id`）填充 `model_info`：有 `run_id` 才是 `Some`。

- [x] **Step 1: 写失败测试**：建项目与成员、插入一条成员消息与一个运行；`set_run` 前 `model_info` 为 `None`；`set_run` 后 `get`/`list` 返回的 `model_info` 与运行上的两个值一致；运行没有记录模型时是 `Some(ModelInfo { None, None })`（表示「有运行但没有记录」，与「旧消息没有运行」区分）；`update_content` 返回的消息也带 `model_info`。

### Task 3: 前端显示

**Files:** `src/types.ts`、`src/lib/modelNote.ts`、`src/lib/modelNote.test.ts`、`src/components/ChatPanel.tsx`（读现有渲染成员消息头部的位置）。

- `src/lib/modelNote.ts`：`export function modelNote(info: ModelInfo | null): string | null`：
  - `info` 为 `null` → `null`（旧消息，不显示）；
  - 有 `reportedModel` → 直接返回它；
  - 没有 `reportedModel` 但有 `requestedModel` → `` `${requestedModel}（请求值，CLI 未回报）` ``；
  - 两者都没有 → `"CLI 默认模型（未回报）"`。
