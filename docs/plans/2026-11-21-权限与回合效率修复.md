# 权限拒绝与回合效率修复

2026-11-21。依据 ESB-AI 一次真实团队运行（30 回合、277 分钟机器时间）的日志分析，修四处会持续复现的损耗。日志结论：58% 的机器时间花在权限受阻后的整轮失败与提权重跑，其中 Claude 成员的 3 次受阻只能转人工，最长空等 12.4 小时；组长 2 次协议出错重发也占回合；1 次 30 分钟超时、1 次上游断流各废掉一个任务回合。

## 1. Claude 的权限拒绝进入自动提权通道

- 现状：`handle_denial` 只对 `DenialSource::Adapter` 自动提权。Codex 适配器会解析命令拒绝，Claude 适配器没有，Claude 的 `This command requires approval` 只能落进成员正文，按成员自述处理 → 人工授权。
- 实测（Claude Code 2.1.330，`--permission-mode acceptEdits`，样本 `src-tauri/tests/fixtures/claude/denied.jsonl`）：拒绝同时出现在 `system/permission_denied`（带 `tool_name`、`decision_reason`）、`tool_result`（`is_error: true`）和 `result.permission_denials[]`。
- 实现：适配器以 `system/permission_denied` 为主信号，`tool_result` 与 `permission_denials` 兜底；每次运行只上报一次 `ToolDenied`，说明里带被拒的工具与命令摘要。仍然只认 CLI 自己输出的事件，成员正文里的「受阻」不触发自动提权。
- 影响：Claude 成员受阻会像 Codex 一样按项目开关自动重跑一次；开关关闭或同一任务已提权过，仍转人工。

## 2. 派工拆小与执行前权限预检

- 组长研判、裁定、验收提示词加入：单个执行任务控制在十分钟左右，更久的拆成多个可独立验证的任务。
- 成员执行提示词加入：开始长任务前先用几秒钟的只读命令确认关键工具（`npm --version`、`psql --version`、`which docker`）；被拦截立即停下、不反复重试或绕路，按既定格式在汇报末尾写 `受阻：<操作>｜<原文摘要>`。
- 目的：把「跑 27 分钟才撞到权限墙」的失败成本提前暴露。

## 3. 协议纠错独立额度

- 现状：组长协议出错后的纠错重发也调用 `reserve`，消耗单条指令的回合额度；ESB-AI 的一次运行里 2 次协议出错直接吃掉 2 个回合。
- 实现：每条指令前 3 次协议纠错不占回合额度（`PROTOCOL_CORRECTIONS_PER_INSTRUCTION`），纠错标记与计数仍落在 `runs.error`，不新增表结构。额度用完后不再重发：保留原文作为普通发言、写系统消息说明额度已用完、指令转等待用户。
- 仍然保留「同一逻辑回合最多一次纠错」的限制，不能叠加重发循环。
- 手册第 4 节与运行设置的提示同步改为：组长、成员与会话重开计入回合，前 3 次协议纠错不占额度。

## 4. 回合上限仍是可配置项，不改默认值

- 默认值继续按手册为 30；`系统设置 → 运行设置 → 单条指令回合总数上限` 支持 1–300，新指令生效。
- 触顶后的等待栏已有「调整上限」深链（上一轮实现），本次不重复改。是否把默认值上调到 45–60，等这批效率修复跑过一轮真实团队后再定。
