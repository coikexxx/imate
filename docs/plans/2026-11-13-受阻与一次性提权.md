# 任务受阻与一次性高权限授权（2026-11-13）

## 背景

「自主进化」项目里，开发哥（Codex）执行任务时因权限被拦，但回合进程正常退出，编排层按 `outcome.status == "ok"` 把任务标成「已完成」。组长在群聊里提出两步：先让受阻可见，再做一次性提权。用户要求：**用户能无感完成任务，高权限授权仍然保留**。

## 实测证据（2026-11-13，Windows 11，仓库外临时 git 仓库）

| 场景 | 结果 |
|---|---|
| Codex 0.167.2 `workspace-write` | 删文件、改文件成功；`git add/commit` 失败：`Unable to create .../.git/index.lock: Permission denied`（exit 1）；回合仍 `turn.completed`、进程 exit 0 |
| Codex `danger-full-access` | 删文件、改文件、`git add`、`git commit` 成功 |
| Codex 同 thread 续接 + `danger-full-access` | 续接后提交成功 |
| Dsh 0.2.2-rc.1 `workspace-write` | 删文件、改文件、`git add/commit` 全部成功，没有拒绝事件 |

结论：**Codex 的真正拦点是 `.git` 写入**，不是删文件；Dsh 当前版本不需要提权。检测必须以命令/工具结果为准，不能只看回合是否正常退出。

## 设计

### 1. 受阻可见

- 适配器把能识别的权限拒绝转成 `AgentEvent::ToolDenied`：
  - Codex：`item.completed` 的 `command_execution` 失败（`status=failed` 或 `exit_code≠0`）且输出含 `Permission denied` / `Access is denied` / `operation not permitted` / 拒绝访问等；
  - Dsh：`tool_result` 的 `status=error` 且 `error.code` 含 `SANDBOX` / `PERMISSION` / `DENIED`，或结果文本像权限拒绝；
  - 普通失败（例如测试失败）不算受阻。
- 执行提示词要求成员在无法绕过时单独写一行 `受阻：<操作>｜<原文摘要>`，作为认不出拒绝时的兜底（标「成员报告」）。
- 拒绝证据区分来源：适配器检测（`DenialSource::Adapter`）与成员报告（`DenialSource::MemberReport`）。只有适配器从 CLI 事件流里识别出的拒绝能触发自动提权；成员报告的受阻一律转人工，必须等用户点卡片。
- `apply_execute` 收到拒绝后：任务状态写 `blocked`（界面「受阻：权限不足」），群聊写系统消息（来源、被拦操作、拒绝原因、授权说明），指令转 `waiting_user`。受阻不取消同批未开始的任务，授权后还能继续。
- 任务行、系统消息和运行结果都不再把这种回合算成完成。

### 2. 无感授权

- 项目级开关「受阻时自动提权」，默认关闭；按项目持久化在 `settings` 的 `project_elevation:<projectId>`。
- 指令创建时快照到 `instructions.elevated_allowed`，之后改开关不影响已有指令。
- 已授权的指令遇到适配器检测到的拒绝：**自动用最高权限续接原会话重跑一次**，系统消息留痕，用户不用点任何东西；成功后恢复原档位。每条任务最多自动提权一次，再被拒就转人工。
- 未授权的指令：群聊出现受阻卡片，「授权并继续」只对这一次重试有效；点击后只把这个任务放回待执行，以最高权限重跑，然后继续同批剩余任务。同一条指令里的其他任务仍按项目开关决定是否自动提权。
- 只有用户能打开开关或点卡片；组长/成员协议里没有提权字段。`runs.elevated` 记录每次提权，便于审计。

## 实现

| 层 | 改动 |
|---|---|
| 数据库 | 迁移 4：`instructions.elevated_allowed`、`runs.elevated`，旧数据默认关闭/未提权 |
| 适配器 | `AgentEvent::ToolDenied`、`Denial`/`DenialSource`；Codex/Dsh 拒绝识别；`set_elevated` 切换 `danger-full-access` |
| runner | `RunOutcome.denial` 收集第一条拒绝证据，适配器拒绝标为 `Adapter` |
| 编排 | `apply_execute` 受阻分支、仅适配器拒绝自动提权重跑、`authorize_blocked_task` 只授权单次重试、任务 `blocked` 状态、提示词补充 |
| 命令 | `get_project_elevation` / `save_project_elevation` / `retry_blocked_task` |
| 前端 | 指令条新增 `elevatedAllowed`；聊天输入区「受阻时自动提权」开关；受阻卡片与任务状态；API |

## 验证

- 后端：`cargo test --lib -- --test-threads=1` → 330 passed、2 ignored。
- 前端：`npm test` → 115 passed（17 个文件）；`npm run build` 通过。
- 新增覆盖：Codex 拒绝/普通失败区分、Dsh 拒绝/普通错误区分、提权命令参数、迁移默认值、无授权受阻、预授权自动重跑一次、二次拒绝不再循环、用户授权后重跑、成员报告兜底、前端任务状态标签。
- 两条授权边界由测试锁住：
  - `member_reported_denial_never_triggers_automatic_elevation`：项目开关打开时，成员正文里的「受阻：…」只让任务进入 `blocked`、指令进入 `waiting_user`，不会调度提权重跑。
  - `manual_authorization_does_not_cover_later_tasks`：手动授权只让当前任务以高权限重跑，同一指令的后续任务仍按普通档运行；再次被拒时停在受阻。

## 已知限制

- 当前只在执行任务（`apply_execute`）上生效；空闲时的 `@成员` 直接回合没有受阻卡片。
- 「已经改了几个文件」无法精确统计，系统消息只给出拒绝原因和操作，文件事实由组长验收与 `git status` 判断。
- 识别到任一权限拒绝就按受阻处理；如果成员随后自己绕过并完成，会多出一次提权重跑（已预授权时）或一次授权卡片（未授权时）。v1 接受这个代价。
- Codex 的 `.git` 拦截只在本机 0.167.2 + Windows 实测；其他版本/平台需要在应用窗口里复验。
- 2026-11-13 已按用户授权完成 Windows 原生受阻卡片、手动单次授权、自动一次重跑与真实 Git 提交；结果见下方补验。

## 2026-11-13 Windows 原生补验

基线 d1b2456 已包含 ProxyAdapter 的 set_elevated / 推理强度透传修复。实际 Codex 普通 .git/index.lock 拒绝后自动重跑一次，运行审计 elevated=1，进程参数及同会话上下文均为 danger-full-access / low；真实提交 75ef02afd05db3988fb0bffcca60bfedb03cf38b 只含 elevation.txt=elevation-ok（12 字节），组长独立核验并完成指令，后续回合恢复 workspace-write / low。不能再只以数据库 elevated 值判定生效。

手动卡片与单次授权说明通过：Codex 被防病毒拦截的特定 WriteAllBytes 脚本在提权后仍失败，应用再次受阻、不循环重跑，失败记录保留。Dsh 本轮普通终端遭 Windows ACL grantWrite 错误，单次手动授权后完成团队文件交付；普通 write/read 直接回合仍可成功。因此文首“Dsh 不需要提权”只代表原采样，不外推为当前所有工具路径。未修改系统安全设置。详细 run ID、实际 sandbox 转换、文件字节及数据恢复见 [Windows 验收记录](../验收记录-2026-11-13-Windows.md)。
