## Claude：补齐 macOS 工具层权限证据

在仓库外执行，提示词经 stdin，参数沿用适配器的 `-p --output-format stream-json --verbose --permission-mode`，显式指定 `--model opus --effort high`。三回合使用同一 session `239db653-0d66-4fc5-be08-d9f733dadbfa`，均正常退出。

| 回合 | 权限回显 | 实际工具与文件事实 |
|---|---|---|

| 同会话执行 | bypassPermissions | 实际调用 Write 并成功创建 `claude-permissions.txt`；正文严格为 `macos-execute-ok`，16 字节，无 BOM、无换行 |

## Codex：当前版本的续接、权限与用量

在同一仓库外目录，使用适配器的 exec/resume 参数、stdin 与 `approval_policy=never`。三个回合使用同一 thread `01a1d4c4-21f1-7811-bc30-9f2017b10b49`，均成功退出。

| 回合 | 实际结果 | 累计 input / output |
|---|---|---|
| read-only | 无工具，准确回复预定标记 | 18330 / 12 |
| workspace-write | command_execution 成功，创建并读取 `codex-permissions.txt`，14 字节严格为 `macos-codex-ok` | 56112 / 174 |

仅从本轮 thread 的会话文件抽取 turn_context 与 token_count，没有读取其他会话正文。上下文确认权限为 read-only → workspace-write → read-only，三个回合均 low；`turn.completed.usage` 与 `total_token_usage` 对上，证明当前版本仍是线程累计值。续接增量 input 为 37782、19226，output 为 162、16，继续支持适配器按可靠基线取差的规则。缓存输入单列，不重复相加，费用未知。第二回合确实执行写入；本轮没有额外制造 Codex 只读写工具失败，不把最后一回合的无工具回复当成工具层拒写。
