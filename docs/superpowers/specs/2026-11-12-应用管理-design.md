# 系统设置：应用管理 设计

日期：2026-11-12　分支：`feat/office-polish`　状态：待用户审阅

## 1. 目标

在系统设置页新增「应用管理」，让用户提前登记、启用各个 CLI，并为每个 CLI 选出允许使用的模型。界面参考 CC Switch：分「已安装」「未安装」两组，每行一个开关，点进去是该 CLI 的详情。

不在本期范围：一键安装或升级 CLI、为 Gemini/OpenCode 等没有适配器的 CLI 写适配器、Pi 适配器（见 `docs/plans/2026-11-11-M5-其余适配器.md`）。

## 2. 已确认的决定

| 问题 | 决定 |
|---|---|
| 「接入」做到什么程度 | 检测登记加开关。自动检测安装状态、版本、路径，可手动指定路径。不做一键安装 |
| 预设哪些 CLI | `KNOWN_CLIS` 里的 5 个：Claude Code、Codex、Grok、DeepSeek Harness、Pi。Pi 无适配器，只列出并置灰，标「暂未支持」。其余 CC Switch 里的 CLI 不放 |
| 模型语义 | 每个 CLI 一份启用模型白名单，加一个可选默认模型 |
| 模型来源 | Grok 读 `grok models`；Dsh 复用现有目录；Claude、Codex 用内置常用列表；每个 CLI 都能手填自定义模型 ID |
| 关闭开关的效果 | 只影响新选：成员表单不再列出，内置助理自动选择时跳过。已有成员照常运行 |

## 3. 数据

复用 `settings` 表（`key TEXT PRIMARY KEY, value TEXT`，与 `dsh_config.rs` 同样的 upsert 写法），每个 CLI 一条，键为 `cli_config:<id>`，值为 JSON（camelCase）：

```json
{
  "enabled": true,
  "customPath": null,
  "models": [{ "id": "sonnet", "label": "sonnet", "custom": false }],
  "defaultModel": null
}
```

规则：

- 没有记录时的默认值：`enabled` 等于该 CLI 是否受支持（Pi 为 `false`，其余为 `true`）。不在后端依赖安装检测，保证测试与现有项目行为不变。界面上未安装的 CLI 一律显示为关闭且不可切换。
- `models` 为空表示不限制。已有成员和未配置白名单的 CLI 都不会被挡住。
- `defaultModel` 非空时必须在 `models` 里。
- `models` 内 `id` 不重复、去首尾空白、非空。
- `customPath` 必须是存在的绝对路径文件；空表示自动检测。
- 保存时整体校验，失败不写入任何字段。
- 记录损坏时读取返回错误，提示重新保存，不静默回退（与 `dsh_config::load` 一致）。

## 4. 后端

新增 `src-tauri/src/cli_config.rs`，并在 `lib.rs` 注册命令。

- `list_cli_configs() -> Vec<CliConfigView>`：每个预设 CLI 一项，合并 `CliInfo`（安装、版本、路径、`supported`）与已保存配置，并带上 `modelsSource`（`auto` 或 `builtin`）。
- `save_cli_config(id, config)`：校验后保存，返回保存后的视图。未知 CLI、`supported == false` 的 CLI 不允许 `enabled: true`。
- `list_cli_models(id) -> CliModelCatalog`：返回「可勾选候选」。
  - `grok`：运行 `grok models`，走现有代理环境（`proxy::resolve` 与 `proxy::overrides`），解析输出。失败时返回内置空列表加错误说明，不抛出，界面仍可手填。
  - `dsh`：不走本命令。前端沿用 `api.listDshModels` 与 `dshModelOptions`，把 `encodeDshModel` 得到的 JSON 串作为模型 `id`（后端只当不透明字符串，保存时用 `dsh_config::parse_selection` 校验）。这样前后端不必各自实现同一个 JSON 键顺序。
  - `claude`、`codex`：内置常用模型列表。
  - 候选与已勾选的合并在前端做纯函数。
- 检测入口：`cli_registry::resolve_cli(id)` 读取 `cli_config:<id>.customPath`，有值则以它为程序路径，不再搜索 PATH。这是对 `cli_registry` 的小改动，`detect_all` 同步生效。

选择规则（集中在一个函数，供各处共用）：

- `is_enabled(id)`：读配置，无记录时按上面的默认值。
- `assistant::choose_cli_id`：自动选择时跳过 `enabled == false` 的 CLI；显式指定一个已关闭的 CLI 时仍报错说明「已在应用管理中关闭」。
- 成员保存校验（`commands.rs` 的创建、更新成员）：新建，或把 CLI 改成另一个时，要求目标 CLI 已启用；只改其他字段的已有成员不检查，避免旧成员因 CLI 被关闭而无法编辑。
- 模型回落：成员 `model` 为空时，在构造 `TurnRequest` 处用该 CLI 的 `defaultModel`。成员自己填了则优先。各适配器已忽略空白模型，不需要改。
- Dsh 的认证方式与 profile 仍由 `dsh_settings` 管理，不并入 `cli_config`。

## 5. 前端

`src/pages/Settings.tsx` 新增第三个分类「应用管理」，内容放在 `src/components/AppManager.tsx`，纯函数放在 `src/lib/cliConfig.ts`。

列表页：

- 分「已安装 · N」「未安装 · N」两组。
- 每行：名称、路径（超长省略）、版本、开关，行尾箭头进入详情。
- 未安装的 CLI 开关置灰，提示「未检测到，可在详情里指定路径」。
- Pi 整行置灰，标「暂未支持」，无开关。

详情页（点击行进入，左上「← 应用管理」返回）：

1. 接入：检测到的路径与版本；手动指定路径输入框；「重新检测」；开关。Dsh 额外嵌入现有 `DshSettingsPanel`（认证方式与 profile）。
2. 模型：候选列表（带勾选）、「刷新」、手填添加、默认模型下拉（只列已勾选项）、「保存」。保存失败保留草稿并显示原因。

成员表单（`AgentForm.tsx`）：

- CLI 下拉只列已启用且受支持的 CLI；编辑已有成员时，当前 CLI 即使已关闭也保留显示并标「已关闭」。
- 模型框：该 CLI 白名单非空时改为下拉，首项为「使用默认（<defaultModel 或 CLI 自带>）」；白名单为空时保持现有输入框。
- Dsh 现有 `DshModelSelect` 的候选按白名单过滤，白名单为空时不过滤。

## 6. 错误与边界

- 检测慢（登录 shell 最多 3 秒）：列表页先显示加载态，不阻塞切换分类。
- `grok models` 超时或联网失败：详情页显示错误，仍可手填。
- 取消勾选一个已被成员使用的模型：允许；已有成员不受影响，成员表单里该值显示为「不在白名单」并保留。
- 同时关闭所有 CLI：成员表单提示「没有已启用的 CLI，请先在设置里启用」；内置助理报现有的「没有已安装且已接入的助理 CLI」类错误。

## 7. 测试

后端（`cargo test`，串行）：

- 配置读写往返；无记录时的默认值；损坏记录报错。
- 校验：`defaultModel` 不在白名单、模型重复或为空、`customPath` 不存在、对不支持的 CLI 启用，均失败且不写入。
- `choose_cli_id` 跳过已关闭 CLI；显式指定已关闭 CLI 报错。
- 成员保存：新选已关闭 CLI 失败；已有成员改其他字段不受影响。
- 模型回落：成员模型为空用 `defaultModel`，成员自填优先。
- `grok models` 输出解析：先用真实 CLI 录制样本存到 `src-tauri/tests/fixtures/grok/models.txt`（仓库目前没有该样本），解析基于样本，不凭印象写。

前端（`npm test`，vitest，纯函数）：

- 已安装/未安装分组与计数。
- 候选与已勾选、自定义模型的合并去重。
- 成员表单的 CLI 选项过滤、模型选项构造（含白名单为空、模型不在白名单）。

窗口验收（用户执行，不在自动测试内）：开关切换、详情保存后重启可见、成员表单联动、Grok 模型刷新。
