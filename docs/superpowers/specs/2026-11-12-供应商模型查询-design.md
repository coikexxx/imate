# 应用管理：按供应商查询 Claude / Codex 模型 设计

日期：2026-11-12　分支：`feat/provider-models`（从 `main` 切出）　状态：待用户审阅

承接 `docs/superpowers/specs/2026-11-12-应用管理-design.md`。应用管理里 Claude 只有 `opus/sonnet/haiku` 三个别名，Codex 没有候选，因为二者在本机通常走自定义供应商，没有官方的列模型命令。本设计让详情页能读到供应商实际提供的模型。

## 1. 目标与范围

- 目标：在「应用管理」详情页，为 Claude Code 和 Codex 读取其配置的自定义供应商所提供的模型，作为白名单的候选。
- 范围：只做 Claude、Codex 的候选来源。Grok（`grok models`）、Dsh（Dsh 目录）不变。
- 不做：不修改 CLI 自己的配置；不把密钥存进应用数据库；不自动重试；不做模型能力探测或定价。

## 2. 已确认的决定

| 问题 | 决定 |
|---|---|
| 候选来源 | 本地目录优先，再查供应商，两者合并去重；都读不到则退回手填 |
| 联网触发 | 详情页新增「从供应商读取」按钮，点了才联网。普通「刷新」只读本地目录，不发密钥 |
| 新增依赖 | 同意新增 `ureq`（同步 HTTP 客户端，rustls）与 `toml` |

## 3. 候选来源与顺序

`list_cli_models(id, fromProvider)` 在 `claude`、`codex` 上按下列顺序合并，先出现者优先，按 `id` 去重：

1. **本地目录**（始终读取，不联网、不用密钥）：仅 Codex。读 `config.toml` 顶层 `model_catalog_json` 指向的文件，取 `models[].slug` 作 `id`，`display_name`（没有则 `slug`）作 `label`。文件不存在、不可读或格式不对时忽略这一层，不报错。
2. **供应商接口**（仅 `fromProvider = true`）：见 §4。
3. **内置候选**（已有）：Claude 的 `opus/sonnet/haiku`；Codex 为空。

`fromProvider = false` 时只合并 1 和 3。Claude 没有本地目录，所以点普通「刷新」仍只有内置三项。

## 4. 读取供应商配置与请求

### 4.1 Codex

- 配置目录：环境变量 `CODEX_HOME`，没有则 `<用户主目录>/.codex`。读其中的 `config.toml`（用 `toml` 解析）。
- 当前供应商：顶层 `model_provider`；取 `[model_providers.<id>]` 表。没有该表、没有 `base_url`，或 `model_provider` 缺失，返回错误「未找到自定义供应商配置，请手填模型」，不回退到官方地址。
- `base_url` 必须是 `http://` 或 `https://` 且有主机名。
- 密钥按顺序判断：
  1. 表内 `experimental_bearer_token` 非空，就用它；
  2. 表内配了 `env_key`：读该环境变量，非空就用；变量未设置或为空则直接返回错误「环境变量 {变量名} 未设置（从图形界面启动的应用可能读不到 shell 里的变量），请手填模型」，不再往下回落（避免把 `auth.json` 里的 OpenAI 官方密钥发给第三方网关）；
  3. 表内没有 `env_key` 时，只有该表 `requires_openai_auth = true`（布尔 true）才读 `<配置目录>/auth.json` 的 `OPENAI_API_KEY`（此时 Codex 自己也会把它发给该供应商）；否则返回错误「未找到该供应商的密钥」。
  `auth.json` 读不到或没有非空的 `OPENAI_API_KEY` 时，同样返回「未找到该供应商的密钥」。
- 请求：`GET {base_url 去掉末尾 /}/models`，头 `Authorization: Bearer <密钥>`、`Accept: application/json`。
- 响应：JSON，取 `data[].id` 为 `id`，`label` 同 `id`。

### 4.2 Claude Code

- 配置来源（后者覆盖前者）：`<CLAUDE_CONFIG_DIR 或 用户主目录/.claude>/settings.json` 的 `env` 对象；进程环境变量。
- 取 `ANTHROPIC_BASE_URL`；没有则返回「未找到自定义供应商配置，请手填模型」，不回退到官方地址。
- 密钥：`ANTHROPIC_AUTH_TOKEN`（头 `Authorization: Bearer`）优先，否则 `ANTHROPIC_API_KEY`（头 `x-api-key`，另加 `anthropic-version: 2023-06-01`）。都没有则返回「未找到该供应商的密钥」。
- 请求：base 末尾已是 `/v1` 时 `GET {base}/models`，否则 `GET {base}/v1/models`。
- 响应：JSON，取 `data[].id` 为 `id`，`display_name`（没有则 `id`）为 `label`。

## 5. 安全约束

- 密钥只在后端读取和使用，不进入任何返回给前端的结构，不写日志，不进错误文本。`CliModelCatalog` 只含模型列表、错误说明，以及用于界面提示的**主机名**（不含路径、查询、账号）。
- 密钥只发给该 CLI 自己配置的 Base URL。不跟随跨主机重定向（禁用重定向，遇到 3xx 按失败处理）。
- 只允许 `http`、`https`。超时 20 秒。响应体最多读 1 MB，超出按失败。模型最多 200 个，超出截断并在 `error` 里说明。
- 错误文本只含状态码或失败类别（如「HTTP 401」「连接超时」「响应格式不对」），不回显响应体，不回显请求头。
- 沿用应用的网络代理设置：`proxy::resolve` 得到的环境覆盖转成 `ureq` 的代理配置；解析代理失败时返回 `error`，不抛出（与 Grok 一致）。
- 界面上按钮旁写明「会把该 CLI 配置里的密钥发给 <主机名>」，主机名来自后端返回，让用户知道发给谁。

Task 2 评审后的实现补充：请求头带 `Accept-Encoding: identity`；响应体限长作用于解码后的字节；非 2xx 不读响应体；SOCKS 代理给出固定提示（暂不支持，请改用 HTTP 代理或直连）。

## 6. 后端设计

新增 `src-tauri/src/provider_models.rs`，职责：解析配置、构造请求、解析响应。对外只暴露：

- `pub struct ProviderEndpoint { pub url: String, pub host: String, auth: Auth }`（`Auth` 私有，不实现 `Debug`/`Serialize`，避免密钥泄露到日志或序列化）。
- `pub fn codex_endpoint(home: &Path, env: &dyn Fn(&str) -> Option<String>) -> Result<ProviderEndpoint, String>`
- `pub fn claude_endpoint(home: &Path, env: &dyn Fn(&str) -> Option<String>) -> Result<ProviderEndpoint, String>`
- `pub fn codex_catalog(home: &Path) -> Vec<CliModel>`（本地目录）
- `pub fn parse_models_response(kind: Kind, body: &str) -> Result<Vec<CliModel>, String>`
- `pub fn fetch_models(endpoint: &ProviderEndpoint, proxy: Option<&str>, http: &dyn Fn(&Request) -> Result<Response, String>) -> Result<Vec<CliModel>, String>`：HTTP 发送函数可注入，测试用假实现，生产用 `ureq`。

`cli_config::list_cli_models` 增加 `from_provider: bool` 参数（Tauri 命令参数名 `fromProvider`），claude/codex 分支调用上述函数并与内置候选合并；`CliModelCatalog` 增加 `providerHost: Option<String>`。合并与降级逻辑抽成纯函数 `merge_catalogs(local, provider, builtin) -> CliModelCatalog`，可测。

`Cargo.toml` 新增：`ureq`（默认特性即可，使用 rustls，不启用 native-tls）、`toml`。

## 7. 前端设计

- `api.listCliModels(id, fromProvider = false)`；`CliModelCatalog` 增加 `providerHost: string | null`。
- `CliDetail`：仅在 `config.id` 为 `claude`、`codex` 时显示「从供应商读取」按钮，点击后以 `fromProvider = true` 调用，结果与当前勾选合并（沿用 `mergeModels`，不冲掉已勾选与手填项）。按钮旁提示「会把该 CLI 配置里的密钥发给 {providerHost 或 '该 CLI 配置的供应商'}」；因为发送前才知道主机，按钮提示文案用后端上次返回的主机名，未知时写「该 CLI 配置的供应商」。
- 读取中按钮置忙；失败显示 `error`，仍可手填。沿用已有的请求序号保护，避免过期响应覆盖。
- 普通「刷新」只读本地目录（`fromProvider = false`）。

## 8. 错误与边界

- Claude 本机没配 `ANTHROPIC_BASE_URL`：点按钮得到「未找到自定义供应商配置，请手填模型」，其余候选不受影响。
- 供应商返回 401/403/404/5xx、超时、格式不对：显示类别说明，保留已有候选和手填项。
- 配置文件缺失或损坏（`config.toml`、`settings.json`、`auth.json`）：该来源视为不可用并给出原因，不影响其他来源。
- 本地目录文件很大或格式不对：忽略并继续。
- 供应商返回的模型 `id` 含控制字符或过长：丢弃该项。

## 9. 测试

后端（`cargo test`，串行；全部不联网、不读真实密钥，用临时目录里的假配置）：

- `codex_endpoint`：只用 `experimental_bearer_token`；用 `env_key` 环境变量；设了 `env_key` 但变量未设置→报「环境变量」错误且不回落；`auth.json` 仅在 `requires_openai_auth = true` 且无 `env_key` 时使用；否则→「未找到该供应商的密钥」；没有 `[model_providers.<id>]`→供应商错误；`base_url` 非法（`ftp://`、无主机）→错误；`CODEX_HOME` 覆盖默认目录；URL 拼接（末尾 `/`）。
- `claude_endpoint`：`settings.json` 的 env 与进程环境覆盖顺序；`AUTH_TOKEN` 优先于 `API_KEY`；base 带或不带 `/v1`；缺 `ANTHROPIC_BASE_URL`；缺密钥。
- `codex_catalog`：解析录制样本（用与本机同结构但脱敏的目录样本，只含 slug、display_name 等非敏感字段）；缺文件、损坏文件返回空。
- `parse_models_response`：OpenAI 形（`data[].id`）与 Anthropic 形（`data[].id`、`display_name`）；空列表；非法 JSON；超过 200 条截断；含控制字符的 id 被丢弃。
- `fetch_models`（注入假 HTTP）：成功；HTTP 401 只报状态码、错误文本不含密钥与响应体；超时；3xx 按失败；响应超过 1 MB 按失败；断言请求头里 Bearer 或 `x-api-key` 正确、且发往 `endpoint.url`。
- 密钥不泄露：`ProviderEndpoint` 没有 `Debug`/`Serialize` 实现（编译期保证）；各错误文本不含密钥字符串（用一个独特的假密钥，断言所有返回文本都不含它）。
- `merge_catalogs`：本地与供应商去重顺序；供应商失败时仍返回本地与内置并带 `error`；`providerHost` 只含主机名。

前端（vitest，纯函数）：沿用 `mergeModels` 已有用例；新增提示文案选择函数（有无 `providerHost`）的用例。

窗口验收（用户执行）：Codex 点普通「刷新」得到本地目录 8 个模型；点「从供应商读取」得到供应商真实模型并与本地合并；Claude 未配供应商时的提示；故意填错 Base URL 或密钥时的错误提示不含密钥；重启后白名单仍在。

- 不改 Grok、Dsh 的候选逻辑，也不改成员表单。
