# 多设备开发指南

本项目会在多台设备（Windows、Intel Mac、Apple Silicon Mac）之间切换开发。本文是各设备的环境清单和协作约定，换设备前后按此核对。

适用设备：

| 设备 | 系统 | 架构 |
| --- | --- | --- |
| Windows PC | Windows 10/11 | x64 |
| Mac A | macOS | Intel (x86_64) 或 Apple Silicon (aarch64) |
| Mac B | macOS | Intel (x86_64) 或 Apple Silicon (aarch64) |

---

## 一、新设备首次配置清单

### 通用（所有设备）

- [ ] 安装 Git，并确认 `git --version` 可用
- [ ] 安装 Node.js LTS（Windows 开发机当前为 v24，其他设备请保持主版本一致），确认 `node -v`、`npm -v`
- [ ] 安装 Rust（通过 rustup，选 stable），确认 `rustc --version`、`cargo --version`
- [ ] 生成 SSH key 并添加到 GitHub（Settings → SSH and GPG keys），用 `ssh -T git@github.com` 验证
- [ ] 安装编辑器：VS Code + Tauri 插件 + rust-analyzer

### Windows

- [ ] 安装 Visual Studio Build Tools，勾选"使用 C++ 的桌面开发"
- [ ] 确认 WebView2 运行时已安装（Windows 10/11 通常自带）
- [ ] Rust 工具链选 `stable-x86_64-pc-windows-msvc`

```bash
winget install Microsoft.VisualStudio.2022.BuildTools --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
winget install Rustlang.Rustup
```

### macOS

- [ ] 安装 Xcode 命令行工具
- [ ] 安装 Rust（不需要 WebView2，系统自带 WebKit）

```bash
xcode-select --install
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

### 克隆并启动

- [ ] 克隆仓库并安装依赖
- [ ] 运行 `npm run tauri dev`，确认窗口弹出且 Greet 按钮能调用 Rust

```bash
git clone git@github.com:coikexxx/imate.git
cd imate
npm install
npm run tauri dev
```

首次编译 Rust 依赖约需 3 分钟，之后是增量编译。

### 配置 Git 作者信息

- [ ] 在仓库内设置作者，保证各设备提交署名一致

```bash
git config user.name coikexxx
git config user.email coikexxx@gmail.com
```

- [ ] 统一换行符：Windows 上建议 `git config core.autocrlf input`，避免 CRLF 污染提交

## 二、日常切换设备的工作流

### 收工（离开当前设备前）

- [ ] `git status` 确认没有遗漏的改动
- [ ] 提交所有改动，哪怕是未完成的，可以用 `wip:` 前缀
- [ ] `git push`，并确认推送成功
- [ ] 不要把未提交的改动留在本机，另一台设备看不到

### 开工（到达新设备后）

- [ ] `git pull`，先同步再动手
- [ ] 如果 `package.json` 或 `package-lock.json` 有变化，运行 `npm install`
- [ ] 如果 `src-tauri/Cargo.toml` 或 `Cargo.lock` 有变化，下次 `tauri dev` 会自动重新编译，无需手动处理
- [ ] 运行 `npm run tauri dev` 确认能启动

### 冲突与分支

- [ ] 同一时间只在一台设备上改同一处，避免冲突
- [ ] 较大的功能开独立分支（如 `feat/xxx`），合并后再删除
- [ ] 遇到冲突时先 `git pull --rebase`，解决后再推送

## 三、环境一致性

跨设备最常见的问题是"这台能跑，那台不行"，多数来自版本不一致。

- [ ] **Node 主版本一致**：建议后续在仓库根目录加 `.nvmrc`，用 nvm 管理
- [ ] **Rust 保持 stable 并定期更新**：`rustup update`。如需严格固定版本，可加 `rust-toolchain.toml`
- [ ] **锁文件必须提交**：`package-lock.json` 和 `src-tauri/Cargo.lock` 都已纳入版本库，不要删除或加入 `.gitignore`
- [ ] **用 `npm ci` 而不是 `npm install` 做干净安装**，保证依赖与锁文件完全一致；只有需要新增或升级依赖时才用 `npm install <包名>`
- [ ] **新增依赖后提交锁文件**：改了 `package.json` 或 `Cargo.toml` 后，对应的锁文件改动要一并提交

## 四、不会同步的内容

以下内容在 `.gitignore` 中，每台设备都要各自生成，这是正常现象：

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 前端依赖 | `node_modules/` | `npm install` 生成 |
| Rust 构建产物 | `src-tauri/target/` | 体积很大，首次编译需几分钟 |
| 前端构建产物 | `dist/` | `npm run build` 生成 |
| Tauri 生成的 schema | `src-tauri/gen/schemas` | 自动生成 |
| 编辑器个人配置 | `.vscode/*`（除 `extensions.json`） | 不共享 |
| 环境变量与密钥 | `.env*`、`*.local` | 见下文，需各设备手动配置 |

- [ ] 如果后续引入 API Key 等密钥，**绝不提交到仓库**，在每台设备本地单独配置
- [ ] 把需要的变量名写入 `.env.example`（只写变量名，不写值），方便新设备照着配

## 五、平台差异注意事项

- [ ] **路径**：代码中不要写死 `\` 或 `/`，Rust 里用 `std::path::PathBuf`，前端用 Tauri 的 `path` API
- [ ] **文件名大小写**：macOS 默认不区分大小写，Windows 同样不区分，Linux CI 区分。导入文件时大小写必须与实际文件名完全一致
- [ ] **换行符**：见上文 `core.autocrlf` 设置
- [ ] **应用数据目录**：用 Tauri 提供的 `app_data_dir` 等 API，不要硬编码用户目录
- [ ] **平台专属代码**：用 Rust 的 `#[cfg(target_os = "windows")]` / `#[cfg(target_os = "macos")]` 隔离，并在两个平台都验证
- [ ] **图标**：`src-tauri/icons/` 同时需要 `icon.ico`（Windows）和 `icon.icns`（macOS），更换应用图标时两个都要更新
- [ ] **快捷键**：mac 用 Cmd，Windows 用 Ctrl，不要只写一套

### Intel Mac 与 Apple Silicon Mac

- [ ] 本地开发时，各台 mac 编译出的是本机架构的程序，互不影响，无需特殊处理
- [ ] `src-tauri/target/` 不要在不同架构的 mac 之间拷贝，会引发链接错误
- [ ] 如果某台 mac 从 Intel 迁移到 Apple Silicon（或反之），删除 `src-tauri/target/` 后重新编译
- [ ] 发布包由 GitHub Actions 同时构建 Intel 与 Apple Silicon 两个版本，不依赖本地机器

## 六、打包与发布

- [ ] **Windows 不能本地构建 mac 包**，mac 包只能在 mac 或 GitHub Actions 上构建
- [ ] 发布通过 `.github/workflows/release.yml` 完成：推送 `v*` 标签或在 Actions 页面手动触发
- [ ] 发布前先把 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 三处版本号改成一致
- [ ] 打标签并推送：

```bash
git tag v0.1.0
git push origin v0.1.0
```

- [ ] 产物生成在 GitHub 的 Releases 页面（草稿状态），检查无误后手动发布
- [ ] 当前 mac 安装包**未签名、未公证**，在其他 mac 上首次打开会被 Gatekeeper 拦截。需要对外分发时，要申请 Apple Developer 账号并在工作流里配置签名与公证
- [ ] 本地试打包可用 `npm run tauri build`，产物在 `src-tauri/target/release/bundle/`

## 七、常见问题排查

| 现象 | 处理 |
| --- | --- |
| `npm install` 报 `ECONNRESET` / 网络错误 | 多为临时网络问题，重试一次；持续失败则配置镜像或代理 |
| `cargo` 下载依赖很慢 | 在 `~/.cargo/config.toml` 配置国内镜像（如 rsproxy） |
| Windows 报找不到 `link.exe` | 未安装 MSVC Build Tools，或安装后未重开终端 |
| `rustc: command not found` | 安装 Rust 后需要重开终端，或确认 `~/.cargo/bin` 在 PATH 中 |
| mac 报 `xcrun: error` / 缺少编译器 | 运行 `xcode-select --install` |
| `tauri dev` 端口 1420 被占用 | 关闭占用进程，或结束上一次残留的 `node` 进程 |
| 拉取代码后启动报错 | 先 `npm install`，仍失败则删除 `node_modules` 后 `npm ci` |
| 编译报奇怪的链接错误 | 删除 `src-tauri/target/` 后重新编译 |
| 提交作者显示为陌生账号 | 检查该设备的 `git config user.name` / `user.email` |

## 八、新增设备自检（最终确认）

- [ ] `node -v`、`npm -v`、`rustc --version`、`cargo --version`、`git --version` 都能输出版本
- [ ] `ssh -T git@github.com` 显示认证成功
- [ ] `git remote -v` 指向 `git@github.com:coikexxx/imate.git`
- [ ] `git config user.name` 与 `user.email` 已设置
- [ ] `npm install` 成功
- [ ] `npm run tauri dev` 弹出窗口，Greet 按钮返回 Rust 的问候语
- [ ] 做一次小改动，提交并推送，在另一台设备拉取验证
