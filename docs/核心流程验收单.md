### B5. 失败、超时、取消、中断只显示请求的模型，并标明未确认

消息旁的灰色小字来自 `src/lib/modelNote.ts`。run 不是 `ok` 时，有请求值则显示「请求的模型（请求值，原因，未确认）」；没有请求值则显示「CLI 默认模型（原因，未确认）」。原因对应：失败是「运行失败」，超时是「运行超时」，取消是「已取消」，中断是「已中断」。不得把 CLI init 回显显示成已经确认的模型。成功运行可以显示 CLI 报告的模型。没有 `run_id` 的历史消息不显示这行字。

| 取消 | 第 4 节 W4 停止 | `（请求值，已取消，未确认）` | 未测 |

### W3. 派工后交付可见

- **操作：** 不中途改指令，等待这条指令走完派工和执行。

### W4. 执行中停止

- **操作：** 再发一条会进入执行的指令。成员已经在执行时，点击按钮「停止」。
- **期望：** 该次运行取消，指令进入等待用户，界面给出重试、补充、放弃。发送能力按等待用户的规则恢复，而不是整个项目永远停在执行中。
- **通过判据：** 指令状态变为等待用户。若该条成员消息带模型小字，应符合 B5 的取消文案。能查数据库时，该 run 的 `status` 为 `cancelled`；没查则记录写明，不把界面通过升格成字段通过。

- **通过判据：** 点击前发送被拒绝；确认后新指令能够发出。没点按钮就能够发送，本步不通过。
- **当前记录：** 未测。`docs/CLI实测记录.md`「M2 Windows 验收补记」（2026-11-11）只做了跨进程自动测试：run 变为 `interrupted`，确认后可以再发送，确认本身不杀子进程。同一节写明应用窗口里的点击没有做。`docs/plans/2026-11-10-M2-单Agent对话.md` Task 11 把这项留在未验收。
