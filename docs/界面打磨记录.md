## 第六次调整：指令回合上限的收尾

2026-11-21 用户在长回合运行后收到「单条指令已达到 30 回合上限」的提示，反馈需要优化。原实现只把指令置为等待用户并写等待原因，界面同时给出重试和补充：重试会直接报「不能靠重试清零」，补充提交后会立刻回到等待用户，两个入口都是死路。

- 到达上限时写一条系统消息说明：已完成的任务与文件保留，检查后放弃本条指令并发新指令即可继续，新指令会读取「系统设置 → 运行设置」里的当前上限。只在运行态转为等待时写一次，重复调度不刷屏。
- 后端补齐两处守卫：额度用尽时补充返回明确错误且不留下队列项；受阻任务的授权重跑也直接拒绝，避免提交后立刻回到等待。
- 等待栏在回合上限时只保留说明、`调整上限` 和「放弃」，隐藏重试、补充输入框与受阻授权；`调整上限` 深链到 `#/settings?tab=runtime`，设置页按 `?tab=` 落到运行设置。其他等待原因的重试、补充、放弃不变。文案补上新指令读取当前上限这条路径。
- 上限本身一直是 `系统设置 → 运行设置 → 单条指令回合总数上限`（1 到 300，新指令开始时冻结）；本次补充提示语「任务多的长指令可以上调」，并让设置页支持直接落到该分类。

验证记录：

- 后端新增 2 项回归：达到上限只写一条系统消息且补充被拒、受阻任务在额度用尽时拒绝授权；扩展原有重试/补充测试。完整串行 `cargo test -- --test-threads=1`：402 项中 400 passed、2 ignored。
- 前端新增 1 项回归：回合上限的等待栏不出现重试、补充与授权，`调整上限` 指向运行设置，放弃仍可用；另加设置页深链 2 项。完整 `npm test` 为 23 个文件、158 项通过，`npm run build` 与 `git diff --check` 通过。
- 浏览器（vite dev，无 Tauri 后端）核对深链：`#/settings?tab=runtime` 选中运行设置，`#/settings` 仍落在应用管理。原生窗口与真实设置读写未执行。
